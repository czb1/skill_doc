# 补丁测试报告对比审阅 (patch-test-report-comparer)

## 触发场景

当你需要**对比两份 .docx 格式的补丁测试报告**（一份为已发布的基线版本，一份为新版本），并找出新版本报告中可能存在的问题时，可使用本 Skill。

典型触发方式：

> "请对比 [新版本补丁测试报告.docx] 与 [基线版本补丁测试报告.docx]，指出新报告中可能存在的问题"

## 能力说明

本 Skill 可自动执行以下检查：

1. **文件解析**：使用 python-docx 库提取 .docx 文件的段落文本与表格内容
2. **结构化对比**：按报告结构（封面、概述、测试策略、测试结果、网络安全、度量表单等）逐模块对比
3. **问题检测**：覆盖 15+ 类常见问题，包括：
   - 版本号、产品名称等元信息不一致
   - 封面页总页数缺失或错误
   - 安全测试相关引用（漏洞列表、病毒扫描链接）未更新
   - 概述与正文中问题单状态前后矛盾
   - 表格数量差异（遗漏表格）
   - 测试周期、版本命名错误
   - 章节结构缺失或弱化
   - 措辞、序号格式不一致
   - 度量表单数据缺失
4. **生成问题清单**：按严重程度（严重/中/低）分类输出，定位到具体章节和表格

## 执行步骤

### 步骤 1：确认环境并安装依赖

```bash
pip install python-docx
```

### 步骤 2：准备文件路径

确定两份报告文件的绝对路径：
- 基线报告（已发布版本）路径
- 新版本报告（待审阅版本）路径

### 步骤 3：运行对比脚本

```bash
python scripts/compare_patch_reports.py \
    --baseline "/path/to/baseline_report.docx" \
    --target "/path/to/new_report.docx"
```

### 步骤 4：审阅输出的问题清单

脚本输出按严重程度分类的问题清单，包含：
- 问题描述（定位到章节/表格编号）
- 建议修复方式

### 步骤 5：人工确认与修复

对于自动检测到的每个问题，人工确认后在新版本报告中修复，然后可再次运行脚本验证是否已修正。

## 检查清单（核心参照）

详细检查项请参阅 `references/checklist.md`。

核心检查维度：

| 维度 | 检查点 |
|------|--------|
| 封面元信息 | 版本号、产品名、总页数 |
| 版本信息一致性 | 各章节引用的版本号应与封面一致 |
| 安全测试内容 | 漏洞列表日期、病毒扫描链接是否更新 |
| 表格结构完整性 | 表格数量、表头字段、行数列数是否匹配 |
| 内容一致性 | 概述与正文描述是否矛盾 |
| 测试周期 | 版本命名、轮次统计是否正确 |
| 修订记录 | 修订记录表是否填写 |
| 度量表单 | 数据表格是否完整 |
| 措辞风格 | 全报告术语、措辞是否统一 |

## 注意事项

- 本 Skill 的对比脚本依赖 python-docx 库，请在运行前安装
- 对比基于文本内容，不验证图片、图表内的文字（如需验证需 OCR 支持）
- 脚本输出的问题清单需要人工复核，避免误报
- 建议在正式发布前运行本 Skill 进行质量把关
